# Slate — Live Multi-Device Blackboard

**Date:** 2026-06-05
**Status:** Approved design — ready for implementation planning

## 1. Overview

Slate is a mobile-friendly web app for drawing on a dark "blackboard" canvas that
syncs **live across every device signed into the same account**. Draw on your phone
to explain something and have it appear in real time on a big screen (TV/projector),
laptop, or tablet. Each account holds **multiple boards**, switched via tabs.

The website is hosted as static files on **GitHub Pages**. All account, storage, and
real-time sync features are provided by **Supabase** (which every device talks to
directly from the browser).

## 2. Core use case

> "I want to draw on my phone to explain something, and pull the same drawing up live
> on a big screen." — and keep several boards I can flip between, on any device I'm
> signed into.

## 3. Locked decisions

| Decision | Choice |
|---|---|
| Account model | **Email + password** login (Supabase Auth) |
| Signup flow | **Email confirmation disabled** — instant signup for a personal tool |
| Sync direction | **Two-way** — any signed-in device can draw; all stay in sync |
| Update speed | **Live, stroke-by-stroke** (sub-second) |
| Boards | **Multiple boards as tabs** — create, rename, delete, reorder |
| Visual style | **Modern dark canvas** + **dotted grid** (grid is toggle on/off) |
| Drawing engine | **Custom canvas: Konva.js + perfect-freehand** |
| Backend | **Supabase** (Auth + Postgres + Realtime) |
| Hosting | **GitHub Pages** (static), auto-deployed via GitHub Actions |
| App name | **Slate** |

## 4. Architecture

```
   Phone            Laptop           Big screen (TV/projector)
     │                 │                      │
     └──────── React web app (same site, any device) ──────────┐
                         │                                      │
              GitHub Pages (static hosting — the website)       │
                         │                                      │
                         ▼                                      │
                    Supabase  ◀───────────────────────────────-┘
              ┌──────────┼───────────────┐
          Auth (email)  Postgres DB   Realtime channels
                      (saved boards)  (live strokes)
```

The website itself is static. All "live account sync" comes from Supabase, reached
directly from each browser.

## 5. Tech stack

- **Vite + React + TypeScript** — app shell (login, tab bar, toolbar, board state).
- **Konva / react-konva** — canvas object engine (gives select / move / resize).
- **perfect-freehand** — natural, pressure-like pen strokes.
- **supabase-js** — auth, database, realtime.
- **PWA manifest + service worker** — "Add to Home Screen" on phone; app-like launch.
- **GitHub Actions** — build and deploy to GitHub Pages on push to `main`.

### Framework note
React is chosen over vanilla because there are several stateful UI surfaces (auth
state, tab bar, active tool, selection, undo stack). Konva handles the canvas;
React handles the chrome around it.

## 6. Data model (Postgres, in Supabase)

**`boards`**
| column | type | notes |
|---|---|---|
| `id` | uuid (pk) | |
| `owner_id` | uuid | = `auth.uid()` |
| `title` | text | tab label |
| `sort_order` | int | tab ordering |
| `created_at` | timestamptz | default now() |

**`objects`** (one row per drawn thing — the "object model")
| column | type | notes |
|---|---|---|
| `id` | uuid (pk) | **generated by the client** before insert |
| `board_id` | uuid (fk → boards) | |
| `owner_id` | uuid | = `auth.uid()` |
| `type` | text | `stroke` \| `line` \| `rect` \| `ellipse` \| `arrow` \| `text` |
| `data` | jsonb | points, color, size, position, text, etc. |
| `updated_at` | timestamptz | for last-writer-wins |
| `deleted` | boolean | soft delete (so deletes sync cleanly) |

### Why an object model (not raw pixels)
Storing each board as a **list of objects** is what makes shapes, text, selection,
move/resize, undo/redo, *and* clean multi-device sync possible. Raw pixel canvases
cannot do any of those well. The chosen visual style only changes how objects are
painted.

### Row-Level Security (RLS) — the real security boundary
- The Supabase **anon/public key is safe to ship** in a static site by design.
- Protection comes from **RLS policies**: a user may only `select/insert/update/delete`
  `boards` and `objects` where `owner_id = auth.uid()`.
- This **must be tested**: sign in as a second user and confirm they cannot read or
  modify the first user's boards.

## 7. Real-time sync — the two-tier flow

Freehand drawing fires ~60–120 pointer events per second. Writing each to the database
would be slow and blow free-tier limits. So we split into two tiers:

1. **In-flight (while the finger is down)** → points stream over a **per-board Supabase
   Realtime _broadcast_ channel**, throttled and batched (multiple points per message).
   *This never touches the database.* Other devices render these live.
2. **On finger-up (object committed)** → the finished object is written **once** to the
   `objects` table for durability. Committed changes propagate to other devices (via
   broadcast and/or `postgres_changes`).
3. **On board open** → a device reads that board's objects from the DB **once** to
   rebuild the current picture, then listens for live updates.

> Non-negotiable rule: never write per-point rows to Postgres.

Exact Realtime message-rate limits and the precise channel/auth wiring will be verified
against current Supabase docs (Context7 / supabase skill) during implementation.

## 8. Conflict model

- Each object carries a **client-generated UUID**.
- Edits are **last-writer-wins** by `updated_at` timestamp.
- Operations are `add` / `update` / `delete` keyed by object id.
- This is sufficient for 1–2 people drawing at once.
- **Out of scope (YAGNI):** CRDT / full concurrent-merge collaboration (Yjs/Automerge).

## 9. Screens & UX

**Login screen** — email + password; sign up / sign in. Instant (no email confirm).

**Board screen**
- **Top tab bar** of the account's boards: `+` add, rename (double-tap/long-press),
  delete, reorder.
- **Toolbar:** pen, eraser, color palette, pen size, shapes (line / rect / ellipse /
  arrow), text, select/move, undo, redo, clear board.
- **Dotted-grid toggle** and **fullscreen toggle**.
- **Dark canvas** with optional dotted grid.

**Touch handling** — `touch-action: none` and `preventDefault` on the canvas so the
phone draws instead of scrolling/zooming.

## 10. Scope

**In v1**
- Pen (color + size), eraser, clear board.
- Shapes: line, rectangle, ellipse, arrow.
- Text labels.
- Select / move / resize objects.
- Undo / redo.
- Dotted-grid toggle, fullscreen toggle.
- Multiple boards as tabs (create / rename / delete / reorder).
- Two-way live sync across devices on one account.
- Email + password auth (instant signup).
- PWA install on phone.

**Deferred (not now)**
- Inserting images.
- Layers.
- Export to PNG / PDF.
- Offline mode.
- Sharing a board with *other* people / accounts.

## 11. Risks & operational notes

- **Free Supabase projects pause after ~7 days of inactivity.** First load after a
  break may need a quick un-pause in the Supabase dashboard. Expected on free tier.
- **Email confirmation** is disabled (one Supabase setting) so signup is instant.
- **Setup the user must do once:** create a free Supabase project (~5 min) and paste
  two public values (project URL + anon key) into the app config. Claude will guide
  this step.
- **GitHub Pages base path:** the Vite `base` must match the repo/Pages path, or assets
  404. To be handled in the deploy config.

## 12. Testing

- **Two-device live sync:** draw in one browser, verify it appears live in another.
- **RLS isolation:** sign in as user B, confirm B cannot read/modify user A's boards.
- **Touch:** draw on a real phone; confirm no scroll/zoom interference; PWA install works.
- **Undo/redo correctness:** including after objects arrive from another device.
- **Persistence:** reload a board and confirm it rebuilds from the DB.
